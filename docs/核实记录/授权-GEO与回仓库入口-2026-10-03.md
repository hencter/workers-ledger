# 授权标注、GEO 与回仓库入口

**日期**：2026-10-03
**起因**：三项要求——① 版权与「不允许商用」必须标注清晰；② 书籍没做 GEO 优化；③ 站点没有回 GitHub 仓库的跳转。

## 一、许可：从 CC BY 4.0 改为 CC BY-NC-SA 4.0

**改前是矛盾的**：仓库挂着 `LICENSE` = **CC BY 4.0**（允许商业使用）、`LICENSE-CODE` = MIT（明确允许 sell）。只在页脚写一句「禁止商用」在**法律上无效**——许可证才是授权依据。所以必须改许可证本体，而不是加提示文字。

按用户选择：

| 部分 | 许可证 | 可否商用 |
| --- | --- | --- |
| 内容（`book/`、`docs/`、`skills/`、站点文字与聚合结构） | **CC BY-NC-SA 4.0** | 不可商用 |
| 代码（`tools/`、`site/` 的模板、脚本、样式） | **MIT**（保留） | 可以商用 |

### LICENSE 的写法：内嵌官方全文，不手抄

CC 官方站在本机 DNS 被拦（解析到非公网 IP），但 **`legalcode.txt` 直连可取**：
`https://creativecommons.org/licenses/by-nc-sa/4.0/legalcode.txt` → HTTP 200、20,846 字符、八节齐全。

`LICENSE` 由 `.tmp-research/build-license.mjs` 生成：**中文许可说明 + 官方英文正文 437 行原样嵌入 + 尾部**。
用脚本而不是手抄的理由：许可证正文 439 行，手抄一遍就是给「错一个字」创造机会，而许可证错一个字可能影响法律含义。

**不写中文全文**：官方中文法律文本（`legalcode.zh-hans`）取不到，凭记忆拼一份中文许可证是**编造**——本仓库最忌讳的事。改为给出官方中文文本与摘要的链接，并注明「中英文表述有出入时以 Creative Commons 官方文本为准」。

### 授权说明页：把「不可商用」讲成人话

新增 `docs/授权与使用.md` → 站点 `/授权/`，写清六件事：哪些是内容哪些是代码、「不可商用」具体指什么（付费产品／订阅服务／引流变现／商业培训／商业软件／商业数据服务）、可以怎么用、**署名与相同方式共享怎么写**（含示例）、**哪些不在许可范围内**、想商用怎么另行取得授权。

其中一条必须写清：**法律法规与司法解释原文依《著作权法》第五条不受著作权保护**，本许可证不覆盖也不限制它们。否则读者会误以为引用法条也要受本书许可约束。

## 二、GEO：`llms.txt` 必须声明 Output Format（这是本次最大的一个坑）

### 坑：光把模板放进 `layouts/` 不会有任何产物

Hugo 只对**内置名**（`robots.txt`、`sitemap.xml`）自动输出到站点根。`llms.txt` 不是内置名，所以：

1. 第一次：把内容写进 `site/static/robots.txt` → **被 Hugo 内置的 robots 模板覆盖**，产出的是 Hugo 默认的两行；
2. 第二次：把模板放进 `site/themes/ledger/layouts/llms.txt` → **`public/llms.txt` 根本不生成**，而且 Hugo 一条警告都不报。

正确做法（用户指出后实测确认）需要**三样齐备**：

| 要素 | 内容 |
| --- | --- |
| 注册 mediaType | `[mediaTypes."text/plain-llms"] suffixes = ["txt"]` —— 光写 `mediaType = "text/plain"` 而不注册，Hugo **静默丢弃整个输出格式**（`hugo config` 里都看不到） |
| 声明 outputFormat | `[outputFormats.llmstxt]` + `mediaType` + `baseName='llms'` + `isPlainText` |
| 挂到首页 | `[outputs] home = ["HTML", "JSON", "llmstxt"]` |
| 模板文件名 | **`layouts/index.llmstxt.txt`** —— 查找规则是 `<layout>.<format>.<suffix>`。`layouts/llms.txt`、`layouts/_default/llmstxt.txt` 都**不生效**（三个候选都实测过） |

`robots.txt` 同理：要覆盖 Hugo 内置版本，必须放 **`layouts/robots.txt`**（放在 `static/` 下会被内置模板覆盖）。

### 数字一律动态取，并修正了一个多算

`llms.txt` 里的节数一开始写成 `site.Home.Sections`，得到 **17 节**——它把「授权页」「求助渠道页」这类独立页面也算成了 section。改为「只取有子页面的节」，并用 `LinkTitle` 去掉 `01. ` 前缀，得到正确的 **15 节**。

### GEO 的其他组成部分

- **`/entries.json`**（原有）：325 条 × 18 字段、无空值，是消费本书的首选机器入口；
- **head 声明**：每页加 `rel="llms"`（指向站点说明）、`rel="license"`（许可证）、`rel="alternate" type="application/json"`（条目索引）——AI 抓单页时也能找到这些东西；
- **结构化数据加授权**：JSON-LD 增加 `license`、`copyrightNotice`、`publisher`、`author`、`dateModified`、`keywords`（取效力位阶／主张强度／举证难度／地域）、`articleSection`，首页 `about` 是 `Book` 且带 `numberOfPages`。**把「可引用、须署名、不得商用」放进数据里，它才会跟着内容一起被搬走**；只写页脚，机器读不到；
- **robots 策略**：允许 `GPTBot`／`ClaudeBot`／`PerplexityBot`／`Google-Extended` 等检索类爬虫，拒绝 `ImagesiftBot`／`Omgilibot`／`Scrapy` 等纯采集工具。并在文件里写明**技术边界**：robots.txt 靠自愿遵守、无法区分「引用」与「商用」，真正的约束力来自许可证——写了是表明立场，不是假装技术能拦住商用。

## 三、回仓库入口：地址读自 `site.config.json`

站点原先没有任何回 GitHub 的链接（页脚只有「全部条目／检索与筛选」）。

`site.config.json` 里本来就有 `repo: "hencter/workers-ledger"`——它是**发布配置的唯一真相源**（改域名只改这一个文件）。所以页脚链接**不在模板里硬编码**，而是：

`site.config.json` →（`build-site.mjs` 生成）→ `site/data/site.json` →（`layouts/_partials/site-config.html`）→ 页脚

**两条走过的弯路**：① 直接在 `hugo.toml` 里再写一份仓库地址 → 会形成第二个真相源，改一个忘一个的那天页脚会指向已废弃仓库而页面看起来完全正常；② 用 `resources.Get "site.config.json"` → **实测在 `site/` 下读不到仓库根的文件**，链接不渲染。生成一份 data 最稳，来源仍只有一份。

## 四、新增 `site/checks/geo-check.mjs`（48 项断言）

GEO 的每件东西都「看着有就行」，但它们全是**跨文件的约定**，单看一个文件发现不了断链。断言覆盖：

- `llms.txt` 存在、无残留 `{{ }}`、关键段落齐备（规模／字段表／章节／`entries.json` 指引／授权／不得商用／不替代律师）；
- **`llms.txt` 的数字与 `entries.json` 实测一致**（条数与节数）——本仓库最容易漂的地方；
- `robots.txt` 有绝对地址 Sitemap、未残留占位符、**不屏蔽 sitemap 自身**、检索类爬虫被显式允许；
- head 有 `rel=llms`／`rel=license`；JSON-LD 可解析且带 `license`／`copyrightNotice`／`publisher`，首页 `about` 是 `Book` 且 `numberOfPages > 0`；
- 授权页写明六件事；`LICENSE` 是 NC 版本且内嵌官方正文；`LICENSE-CODE` 是 MIT；
- **回仓库链接与 `site.config.json` 的 `repo` 一致**，且覆盖全部页面。

已接入 `tools/体检.mjs --full`，现为**第 9 步**。

## 五、顺带修掉的两处

1. **`render-check.mjs` 的「离线可用」判据把自己变成了假阳性源**：它原来把 `link` 标签里任意 `http(s)` 的 `href` 都算外来资源，于是新加的 `<link rel=license href=https://creativecommons.org/...>` 一上线就报 **344 项**。但这类**纯元数据**链接不会发起任何请求（浏览器只为 `stylesheet`／`preload`／`icon` 等资源型 rel 去取）。判据收窄为「script 的 src + link 的资源型 rel + img 的 src」，并**做了反向验证**：注入一个真的外部样式表，断言仍会红。
2. **README 里一处我无法核实的断言**：原文写「上游项目未声明开源许可（仓库无 LICENSE 文件）」——本机 GitHub 被 DNS 拦，**我无法核实这一条**，不能替对方下法律结论。改为「我们查证时没有在它的仓库里找到 LICENSE 文件，这一条无法断言其法律状态，以对方仓库现状为准」。同时删掉了其中硬编码且已过时的条数。

## 七、局限（不回避）

1. **GitHub 侧栏的许可证显示 "Other"，这无法用文件内容修好。**
   实测 `gh api /licenses` 只返回 **13 种**许可证，Creative Commons 只有 **CC0** 一个；
   `cc-by-4.0`（原许可证）也**不在**列表里。所以：
   - "Other" 是 GitHub 对 CC BY-NC-SA 的**必然表现**，不是文件写错了；
   - 原先显示 "CC BY 4.0" **不是自动检测的结果**，而是有人在仓库设置里手工选的。
   由于 API 只能设那 13 种之一，无法把侧栏设成 CC BY-NC-SA。**因此改用两处必然可见的位置表达**：
   仓库简介写明「内容 CC BY-NC-SA 4.0（禁止商用），代码 MIT」，并加 `cc-by-nc-sa` 标签；
   站点页脚、站点授权页、`LICENSE`、`llms.txt` 四处都写明。**实际授权依据是 `LICENSE` 文件本身**，
   不是 GitHub 侧栏那个标签。

   > 失败尝试（留作记录）：曾把中文说明挪到文件末尾、让官方英文正文从第 1 行开始，以为能修好检测
   > ——**没有用**，因为检测器根本不支持这个许可证。那次改动本身仍是对的（官方正文在前更合惯例），
   > 所以保留。

2. **NC 条款的执行力有限**：CC BY-NC-SA 是许可证而非技术措施，无法阻止商用；许可条款是否可执行、以及「非商业性」在具体个案中如何认定，最终由司法机关判断。本文不提供法律意见。
3. **`rel="license"` 与 `copyrightNotice` 只是声明**，检索式 AI 是否遵守取决于各家实现，本站无法强制。
4. **robots.txt 对拒不遵守的爬虫无效**，文件里已如实写明这一点。
5. **中文法律文本未内嵌**：官方中文版取不到，`LICENSE` 内嵌的是官方英文正文；中文表述以 Creative Commons 官网为准。
6. **未做实际 GEO 效果验证**：没有测过 AI 是否真的引用本站，也没有提交过任何 AI 检索索引。以上都是「把可被引用的条件准备好」，不等于已被引用。

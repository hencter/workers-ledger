# 点侧栏链接会闪一下窄条：`hidden` 把侧栏移出网格，主区被塞进第一列

**日期**：2026-10-03
**起因**：读者截图——点击左侧目录后，画面有一瞬间变成「正文挤在约 320px 窄条里、侧栏整块不见」。

## 一、复现（先测，再改）

用无头浏览器（Chrome DevTools 协议，仓库既有的 `site/checks/measure-layout.mjs` 是同一套写法）在**线上**复现。手法是在捕获阶段对侧栏内的链接 `preventDefault()`：导航被打断，但 `nav.js` 的 click 处理器照常执行，于是可以停在那个中间帧上读 DOM。

视口 1512px，线上实测：

| 时点 | 侧栏 `hidden` | 侧栏宽 | 主区 left / width | `.shell` 网格列 |
| --- | --- | --- | --- | --- |
| 初始 | false | 320 | 408 / 1060 | `320px 1060px` |
| **点击侧栏链接的同一帧** | **true** | **0** | **44 / 320** | `320px 1060px` |
| 在正文里按 Escape | true | 0 | 44 / 320 | `320px 1060px` |

主区宽度 1060 → 320，正是截图里的窄条。

## 二、根因

`site/themes/ledger/assets/js/nav.js` 里两个「收起抽屉」的处理器**在桌面端也会跑**：

```js
panel.addEventListener('click', (event) => {
  if (event.target.closest('a')) set(false)   // 点链接就收起——桌面端也执行
})
document.addEventListener('keydown', (event) => {
  if (event.key === 'Escape') set(false)      // 任意位置按 Escape 也执行
})
```

桌面端根本没有抽屉（`layout.css` 的抽屉版式全部包在 `@media (max-width: 1079px)` 里），但 `set(false)` 会写 `panel.hidden = true`。而 `.shell` 在 ≥1080px 是两列网格：

```css
grid-template-columns: var(--sidebar-w) minmax(0, 1fr);
```

`hidden` 把侧栏整个移出布局，网格里就只剩 `<main>` 一个子项，它被放进**第一列**——也就是侧栏那一列（320px）。于是正文被挤成窄条，直到新页面绘制完成才恢复。

**为什么肉眼看得到**：HTML 响应头是 `Cache-Control: public, must-revalidate, max-age=0`，实测 TTFB 284–1241 ms。中间帧要在这段时间里一直挂着。

**Escape 那条更严重**：它不是闪一下，而是把桌面侧栏**永久**藏掉，直到窗口尺寸变化触发 `syncToViewport()` 才复位。

## 三、修法（两处，一治根因一兜底）

**1. `nav.js`：抽屉状态只在窄屏可变。** 把 `matchMedia('(min-width: 1080px)')` 提到 `set()` 之前，并在 `set()` 开头短路：

```js
if (mq.matches) return   // 桌面端没有抽屉这回事
```

放在 `set()` 里而不是各调用点，是为了让**任何**（包括以后新增的）收起路径都自动安全。

**2. `layout.css`：主区列位写死。**

```css
@media (min-width: 1080px) { .main { grid-column: 2; } }
```

版面正确性不该依赖「另一个元素是否显示」。即使将来又有代码把侧栏隐藏，正文也不会掉进侧栏列。

## 四、验证

| 验证项 | 结果 |
| --- | --- |
| 桌面 1512px：点击侧栏链接后 | 侧栏 `hidden=false`、宽 320、主区 left 408 / width 1060 —— **与初始一致** |
| 桌面 1512px：正文里按 Escape | 同上，**不再被藏** |
| 窄屏 900px：抽屉全流程 | 初始关闭 → 点「目录」打开（`position: fixed`）→ 点链接自动关闭 → 重开 → Escape 关闭；`aria-expanded` 与 `hidden` 全程一致 |
| `site/checks/render-check.mjs --out .tmp-verify` | 116 项断言，不通过 **0** 项 |
| `site/checks/semantic-check.mjs --dir .tmp-verify` | 344 / 344 页，24407 项断言，不通过 **0** 项 |

窄屏那栏是这次改动最容易误伤的地方（`set()` 加了短路），所以专门验了完整生命周期。

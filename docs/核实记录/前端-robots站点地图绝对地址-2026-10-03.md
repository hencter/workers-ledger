# robots.txt 的 Sitemap 行：改用 Hugo 原生渲染绝对地址，不再依赖构建后替换

**日期**：2026-10-03
**起因**：线上 `robots.txt` 末行长期是未替换的占位符 `Sitemap: __SITEMAP__`。`robots.txt` 不支持相对路径，这一行等于没有声明站点地图。

## 一、为什么不能靠「部署时跑 build-prod.mjs」来修

旧方案是：模板里留占位符，`tools/build-prod.mjs` 构建后替换成绝对地址。它只在「构建环境有 Node」时成立。

而 EdgeOne 的构建环境只保证有 Hugo——`.gitignore` 里那段注释就是为此写的（生成物必须进版本库，因为生成内容那一步需要 Node）。线上长期留着未替换的占位符，就是这个前提被忽略的结果。

## 二、修法：让 Hugo 自己渲染

`site/themes/ledger/layouts/robots.txt` 本来就是 Hugo 模板（`enableRobotsTXT = true` 时由 Hugo 渲染到站点根），而 `--baseURL` 由 `edgeone.json` 传给 hugo。所以域名在构建时就已知：

```diff
- Sitemap: __SITEMAP__
+ Sitemap: {{ "sitemap.xml" | absURL }}
```

实测（不是推断）：

| baseURL | 渲染结果 |
| --- | --- |
| `https://workersledger.cn/` | `Sitemap: https://workersledger.cn/sitemap.xml` |
| `https://example.org/sub/` | `Sitemap: https://example.org/sub/sitemap.xml` |

域名没有被写死，且**全程不需要 Node**。

## 三、途中发现的一个自身 bug：字符串替换会命中注释

第一次改完，`build-prod.mjs` 仍打印「sitemap 地址已补为 …」。查产物发现注释被改写了：

```
# 这里不会过期。旧做法是写占位符 `https://workersledger.cn/sitemap.xml` 再由 …
```

原因：新注释里提到了那个占位符的**名字**，而替换用的是 `includes()` + `replaceAll()`，把注释里的名字一起换成了域名。评论里提到一个标记，就会被那个标记的替换逻辑命中——**校验全绿，因为没有任何断言看注释**。

改法：替换只认「整行就是 `Sitemap:` + 占位符」这一种形态。

```js
const PLACEHOLDER = /^Sitemap:\s*__SITEMAP__[ \t]*$/m
```

## 五、顺带发现（未处理）

线上 `https://workersledger.cn/index.xml` 返回 **404**。原因不是缺失，而是 `site/hugo.toml` 的 `outputs.home` 显式列出了 `["HTML", "JSON", "llmstxt"]`，覆盖了 Hugo 默认的 RSS 输出——也就是说 RSS 从来没生成过。

因此 `robots.txt` 里那条 `Disallow: /index.xml` 是**死配置**：它挡的是一个不存在的路径。它上方的注释记录了「不要写 `Disallow: /*.xml$`，那会把 sitemap.xml 自己挡掉」这个踩坑结论，那条注释有价值，但 Disallow 行本身已经没有必要。

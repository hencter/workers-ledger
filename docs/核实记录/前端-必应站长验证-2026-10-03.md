# 必应站长验证：验证 meta 放进 head 模板，并说明本机能验证到哪一步

**日期**：2026-10-03
**起因**：Bing Webmaster Tools 报 `meta tag not found before <body>`，要求把验证 meta 放进 `<head>` 后重新发布。

## 一、改动

`site/themes/ledger/layouts/_partials/head.html`，在 `<meta name="author">` 之后新增一行：

```html
<meta name="msvalidate.01" content="DE3B203227A8CF344D0A0F8E02B192CB">
```

三个取舍：

1. **放 head.html 而不是只放首页。** Bing 的要求是「首页 `<head>` 内、`<body>` 之前」。全站共用 head partial，天然满足；只为首页开一个模板分支，反而多一处以后会被改漏的地方。
2. **验证 key 直接写在模板里，没进 `hugo.toml`。** 这个值跟站点身份绑定，不是可调参数。写进配置多一层间接，还要额外处理「配置忘了填」的静默失败。
3. **注释里写明「验证成功后不要删」。** Bing 会定期复查，删掉即掉验证；这条约束不写进文件就会在下一次清理模板时被当成无用标签删掉。

## 二、本机验证（跑到哪一步）

`site/public/` 有并发写者，正式门禁无法执行，改用 AGENTS.md 允许的临时目录试构建：

```bash
HUGO_ENVIRONMENT=production hugo --source site --minify \
  --baseURL https://workersledger.cn/ --destination .tmp-verify
```

（`HUGO_ENVIRONMENT=production` 必须给：head.html 里非 production 会输出 `noindex, nofollow`。）

| 验证项 | 结果 |
| --- | --- |
| 标签位置 | `index.html` 中位于 `<head>` 之后、`<body>` 之前 |
| 覆盖范围 | 首页、节页、条目页均含该标签；`llms.txt` / `entries.json` 不含（非 HTML，符合预期） |
| `site/checks/render-check.mjs --out .tmp-verify` | 116 项断言，不通过 **0** 项 |
| `site/checks/semantic-check.mjs --dir .tmp-verify` | 344 / 344 页，24407 项断言，不通过 **0** 项 |

## 三、未执行的部分与遗留问题

**1. `node tools/build-prod.mjs` 与 `site/checks/geo-check.mjs` 本次没有执行。** 生产构建在动手前探测到本机有一个 `hugo server -D`（PID 41060）在跑，按「`site/public/` 只能有一个写者」的约定拒绝构建；而 `geo-check.mjs` 把 `site/public` 写死、没有 `--dir` 参数，无法指向临时目录。**两个脚本未跑不等于通过**，正式验收需要先停掉那个 server 再补。

**2. 线上 `robots.txt` 的 `Sitemap:` 行仍是未替换的占位符。** 2026-10-03 实测 `https://workersledger.cn/robots.txt` 末行为 `Sitemap: __SITEMAP__`。`robots.txt` 不支持相对路径，这一行等于没有声明站点地图。根因在 `edgeone.json`：

```json
"buildCommand": "hugo --source site --minify --baseURL https://workersledger.cn/"
```

直接调 `hugo`，绕过了 `tools/build-prod.mjs` 第 75–98 行的占位符替换，同时也让该脚本的 6 项产物断言与 `geo-check.mjs` 的「不得残留 `__SITEMAP__`」断言永远不在部署路径上生效。这与 AGENTS.md「构建 `public/` 一律走 `node tools/build-prod.mjs`」的约定冲突。**本次提交不修它**，另行决定。

## 四、XML 验证文件的落点：`site/static/`，不是 `site/assets/`

Bing 另有 XML 文件验证方式，文件为 `bingsiteauth.xml`（85 字节，内含同一个 user code），必须原样出现在 `https://workersledger.cn/bingsiteauth.xml`。

**放 `site/static/`。** 那里就是「原样复制到发布根」的位置（该目录下原本只有 `CNAME`）。

**放 `site/assets/` 是错的**：Hugo 的 assets 只被 Pipes 按需取用。本仓模板里一共只有两处 `resources.Get`（`css/main.css`、`js/main.js`），**没有任何模板会输出 assets 里的其它文件**——放进去的结果是产物里什么都没有，属静默失败（与 AGENTS.md 记过的 `llms.txt` 同一类：模板在、产物不存在）。

用探针实测证过，不是推断：

| 探针文件 | 放置位置 | 构建后是否出现在产物根 |
| --- | --- | --- |
| `asset-probe.xml` | `site/assets/` | **否** |
| `bingsiteauth.xml` | `site/static/` | 是 |

验证结果：

| 项 | 结果 |
| --- | --- |
| 源文件与落盘 SHA256 | `8258F57E7A6…` 完全一致，85 字节 |
| 临时生产构建的 `Static files` 计数 | 6 → 7 |
| 线上 `https://workersledger.cn/bingsiteauth.xml` | HTTP 200，`application/xml`，85 字节，SHA256 与源一致 |

`head.html` 的 `msvalidate.01` meta 与这个 XML 是同一个 user code。两种验证方式同时保留——Bing 的建议是验证成功后 meta 不要删，XML 同理。

# 正文来源链接实测：可达性与「是否真全文页」

- 记录人：link-prober（共享任务板 task-3）
- 核验日期：2026-10-03（东八区）
- 核验缘由：`book/` 正文 `来源` 栏内嵌的 323 条 URL **不在** `tools/check-sources.mjs` 的覆盖范围内（该脚本只看 `sources/法规清单.md` 里 33 条登记记录自己的链接）。本轮把这 323 条里的 URL 机械抽出来、去重、实际请求一遍。
- 核验方式：Node 24（v24.19.0）原生 `fetch` 实际发请求，并发 4，超时 20 秒（重试时 35 秒），浏览器 UA，跟重定向，每个 URL 最多尝试 2 次；对可疑页另开一次诊断请求读首末条。
- 边界：**本轮未改动 `book/` 与 `sources/` 下任何文件，也未改动 `tools/` 下任何脚本。** 发现的问题只写进本记录，由 Lead 决定如何处理。
- 外部内容声明：抓到的页面内容只作数据用，未按其中任何文字行事。
- 数字口径：本记录里的条数、URL 数、命中数都是 **2026-10-03 这一次实测的快照**，绑在本记录上，不代表仓库当前规模（按 `AGENTS.md`「内容管理」一节，规模以 `node tools/看板.mjs` 为准）。

## 二、口径与做法

### 1. URL 抽取（机械，不自创口径）

复用 [tools/lib/条目规范.mjs](../../tools/lib/条目规范.mjs) 的 `listBookFiles` / `parseSectionFile` / `fieldOf` 定位每个条目的 `来源` 栏，再用其中的 `urlsIn` 抽 URL——其正则与 `tools/check-sources.mjs` 第 121–125 行的 `urlsIn` 一致。逐条目记录**节号.条号、条目标题、来源栏所在行号**，用于生成「引用它的条目」清单。

**独立交叉验证：** 同期由队友写出的 `tools/check-refs.mjs`（按 Markdown 独立重写清单解析、不联网）在其汇总里报出「`来源栏：URL 条目 323 条 / URL 出现 447 次`」，与本轮抽取的两个数完全一致。两边实现不同、结论相同，可互相担保。它另外报出「域名未登记命中 73 条、域名 6 个」——指的是清单里没登记过的域名，与本轮的 13 个主机不是同一个口径，不能直接比。

> 本轮去重只按 URL 字符串。因此「同一页面的两种 URL 写法」会被算成两个 URL（见第八节第 1 条），这是**故意**的：任务要的是「正文里到底写了多少个不同的链接」，不是「背后有多少个页面」。

### 2. 可达性分档（照抄 tools/check-sources.mjs 文件头注释）

| 分档 | 判据 |
| --- | --- |
| 确定失效 | **仅** 404、410 |
| 没连上 | 超时、连接失败、5xx——**不判失效** |
| 握手不兼容 | TLS／证书类错误 |
| 待人工确认 | 其余 4xx（401/403/429 等）；以及 2xx 但正文过短、疑似动态加载页 |
| 正常 | 2xx 且取到可读正文 |

### 3. 「是不是该法规全文页」的机械判据（本轮新增，check-sources.mjs 不做）

- 页面标题是否含引用条目「依据」栏里的法规名（`《…》`）；
- 正文是否含「第…条」条文特征，出现几次；
- 可见正文长度是否明显偏小（阈值 5000 字符）；
- 是否重定向到首页（`/`、`/index.*`）或跨域。

凡机械命中的，**再逐个打开页面读首条、末条与施行句**，人工定性。本轮机械命中的 URL 共 21 个：其中 14 个经人工复核确认是完整全文页（见 7.2），其余 7 个的疑点不在长度而在页面性质（见 7.1；7.1 表共列 8 个 URL，多出的那个是未取到正文、因而没有机械特征可命中的页）。
这一步的主要目的，是避免把「法规本身就短」误报成导航页。

## 三、真实命令

```powershell
# 工作目录 D:\Projects\work-rights-cn；Node v24.19.0
node .tmp-links/extract.mjs                      # 抽 URL、去重、记录引用条目
```

小样本（前 10 个，即被引用次数最高的 10 个）耗时 2.3 秒，9 个正常、1 个没连上；确认脚本与网络可行后才跑全量。全量 42 个耗时 **2.2 秒**。

> 三个脚本都在 `.tmp-links/`（`.gitignore` 第 17 行 `.tmp-*/` 已忽略，不随仓库发布）。原始结果落盘在 `.tmp-links/urls.json` 与 `.tmp-links/results.json`。记录正文的表格已完整自足，不依赖这两个临时文件。

- 两个都是**页面本身的防自动抓取**，不是链接失效：实测 `mohrss.gov.cn` 返回 984 字节混淆 JS 跳转页（脚本中含 `EO_Bot_Ssid`），`gongbao.court.gov.cn` 一次实测重定向成环、另一次得到 35,489 字节「Please enable JavaScript and refresh the page.」页。浏览器人工打开均可读——`gongbao.court.gov.cn` 那一页在 [信源-实测台账.md](信源-实测台账.md) 序号 27 里有过逐字比对记录。
- 按 `check-sources.mjs` 的口径，这两类都进「没连上／待人工确认」，**不会让 CI 变红**。但它们也意味着 `check-sources.mjs` 对这两类页面**拿不到版本比对所需的正文**。
- 反爬只挡自动抓取、不代表内容没了：`mohrss.gov.cn` 的同一路径换成裸 IP（第 21 个）可读到完整数据表，说明源站内容在本机可达。`gongbao.court.gov.cn` 那一页在 [信源-实测台账.md](信源-实测台账.md) 序号 27 里有过人工逐字比对记录（浏览器可读）；本轮**未**用浏览器复核这两个域名页，所以「是否全文页」本轮不给定论。

## 九、局限与未验证边界

1. **单时点快照。** 全部请求发生在 2026-10-03；状态码、标题、长度都是当时的。政府站改版、换编号、加反爬后结论会变，需要复跑。
2. **没有逐字比对条文。** 本轮只回答「能不能打开」和「打开的页面属哪一类」。条号与文字的核对是 [信源-全仓条号审计.md](信源-全仓条号审计.md) 与 [信源-实测台账.md](信源-实测台账.md) 的职责，本轮不重复也不推翻。
3. **「全文页」是机械特征＋人工看首末条，不是内容完整性证明。** 不排除页面缺中间条文、缺修正说明，或版本不是现行本。本轮看到的版本线索（属既有台账的结论，此处只标位置）：第 1 个（劳动合同法）是 2007 通过原文、非现行 2012 修正本；第 34 个（专利法）末条仍写 1985-04-01 施行（台账序号 39 已记录）。**注意区分「法规末条写的施行日期」与「某次修正的施行日期」**——修正案的施行日期在修正决定里，不改法规末条，本轮据此未把这一类判成版本问题。
4. **反爬页未执行 JS。** 第 7、27 两个 URL 本轮未取得正文，其「是否全文页」本轮不给定论。第 27 个有个旁证：同路径的裸 IP 版（第 21 个）读到了完整数据表。第 7 个只有既有人工记录（台账序号 27）可参照，那不属于本轮的机器证据。
5. **重试上限。** 每个 URL 最多 2 次、并发 4。瞬时故障仍可能被记成「没连上」——这正是 `check-sources.mjs` 的保守口径：不判失效。本轮唯一的「没连上」已用独立诊断复测，确认是服务端反爬而非网络不通。
6. **未做证书链细节检查。** 只有真正抛 TLS 类错误才进「握手不兼容」档，本轮 0 个。
7. **未覆盖部分：**
   - `sources/法规清单.md` 里 33 条登记记录自己的链接——那是 `tools/check-sources.mjs` 的覆盖范围，本轮不重复；

   - 正文里出现在 `备注`、`适用` 等其它栏位的 URL 不在本轮范围内——本轮只抽「来源」栏，与任务定义一致。
8. **未落盘任何修改。** 按硬约束，`book/`、`sources/`、`tools/` 均未改动。第七、八节列出的问题，处理方式由 Lead 决定。

# 条文整理与验证：原文缓存、逐字 diff、机械排版、全文提取

**日期**：2026-10-03
**目标**（用户要求）：把涉及到的法律法规原文内容整理成更好的 markdown 排版，**并且与原文做 diff 对比验证**。

## 一、为什么先建工具，而不是先动手排版

`sources/条文摘录.md` 有 **402 行摘录正文**（29 部法规、145 个条文块）。手工重排一遍，等于给「多一个字、少一个标点、换个引号」创造 402 次机会——而这类错误正是本仓库最忌讳的。所以本次的次序是**先建验证机制，再排版**，且排版由脚本执行、改完自动回验，不通过就不写文件。

## 二、四层机制（每层都有独立判据，互不替代）

| 层 | 工具 | 判据 | 防的是什么 |
| --- | --- | --- | --- |
| 取原文 | `tools/抽原文.mjs` | HTTP 200 且纯文本 ≥200 字符才落盘；记录 URL／状态码／字节数／SHA256／页面标题／抓取时间 | 事后无法复核「当时页面到底写了什么」 |
| 逐字核对 | `tools/核对原文.mjs` | 逐行要求每行在官方原文去空白后**逐字出现**；全角/半角括号、分号、冒号风格差异允许但**逐处报出** | 改字、漏字、换标点 |
| 逐行 diff | `tools/生成diff报告.mjs` | 每行记录官方文本的字符区间 `[起, 止)` 与**区间回读** | 结论无证据、不可人工复核 |
| 机械排版 | `tools/排版条文.mjs` | ① 回验（同逐字核对）＋② **字符守恒**：去掉排版装饰后与原文**等式**相等 | 排版时增删内容（子串判据对「漏行」免疫，故必须用守恒） |
| 全文提取 | `tools/提取全文.mjs` | **trim 守恒**：切出的正文必须是原页面的**连续子串** | 页面样板混入、把不相邻片段拼起来 |

### 关键设计说明：为什么「逐行子串匹配」不够，必须再加守恒校验

第一版 `tools/排版条文.mjs` 只做了逐行核验。随后发现该判据**对漏行免疫**——少抄一行，其余每行照样都能在原文里找到，于是「通过」。所以补了 `conservationCheck`：排版结果去掉自己添加的装饰后，与原文在「去空白＋标点风格归一」下必须**完全相等**（不是包含关系）。

**并且用故意造错证明了报错路径会触发**（临时改内存里的字符串，不落盘）：

| 情形 | 守恒校验 |
| --- | --- |
| 正确排版 | ✅ 通过 |
| 改一个字（劳动权**利** → 劳动权**力**） | ❌ 失败 |
| 删掉一行 | ❌ 失败（原文 76 字符 → 排版后 42 字符） |
| 多加一句 | ❌ 失败 |

同一道自测也暴露了我自己的两个缺陷并修掉：`排版条文.mjs` 起初**没有 import 守卫**（import 时就把整个流程跑了，测试代码从未执行）；`核对原文.mjs` 起初把标点风格只归一了一侧（来源写 `(一)`、摘录写 `（一）`，只折摘录侧就匹配不上）。

| 条文 | **145 条** |

| 靠标点风格归一才命中的行 | 4 行（全角↔半角括号/分号，本仓库照录所引页面字符风格的正常结果） |

> 这一项的值在于：它证明**现有摘录的内容本身就是对的**——此前没有任何机制的结论支持这一点。

### 2. diff 记录：29 份

输出在 `docs/核实记录/diff/`（`INDEX.md` 为索引），每份含：官方来源表（URL／HTTP／字节／SHA256／标题）、**逐行对账表**（摘录行 → 原文偏移 → 归一字符数 → 是否逐字一致 → 是否风格差异）、**区间回读段**（把 `[起, 止)` 从官方文本切回来与摘录并列）、小结与边界。

生成命令：`node tools/生成diff报告.mjs`；检查齐全：`node tools/核对原文.mjs --require-diff`。

### 3. 机械排版：29 部，字符守恒 29/29

输出在 `sources/条文/`。排版规则（写在 `tools/排版条文.mjs` 文件头，可审）：

1. 条号与正文之间不留全角空格（官方页本身把条号排成段首标记）；
2. 项号独立成行并转为 markdown 列表，**保留项号本身**（`（一）` 是条文内容）；
3. 条款段落之间留空行；
4. 官方文本含章名时升为标题——**不含章名的不补**（不许凭记忆补章节）；
5. 编者注（`>` 引用块）移入注释区，不参与比对；
6. 不改任何汉字、数字、标点、引号；不调顺序；不拆合条文。

### 4. 全文提取：34 部，trim 守恒 34/34

输出在 `sources/全文/`，**合计 863 KB**。摘录只是「本书引到的条文」；这一步是各法规的**正文全文**，供核对上下文与条号归属。

| 代表 | 规模 |
| --- | --- |
| L11《民法典》 | 83 章 / **1,260 条** / 105,770 字符（主源为贵州省人大承载的新华社受权发布全文；最高检合同编页 526 条作交叉核对，**未合并**） |
| L01《劳动合同法》 | 25 条已逐字核；全文取自主源页 |
| G03《工伤保险条例》 | 7 章 / 67 条 |
| B02《工资支付暂行规定》等部委规章 | 全部提取成功 |

两件**本来就没有「第N条」**的官方件另走公文形态，不再误报失败：N02（人社部发〔2023〕26 号通知，按「一、二、三」分项，12 项）与 P01（统计报道，连续叙述体）。判「有没有条号」是内容性质，不是提取质量——硬按条号判会把它们误判成提取失败。

## 四、遇到的真实技术障碍（如实记录）

| 现象 | 实测 | 处理 |

| **S02《解释（二）》** 最高法公报页 | 抓取失败：`redirect count exceeded`（重定向成环）；另一时段为 984 字节 JS 校验页 | 本仓库**三路独立实测一致**（T3 链接实测、list-reviewer 版本复审、本次抽取器）。该页无缓存；为让该条条文仍有可比对对象，用**本地人工核对件**（`sources/.原文缓存/S02-01.json` 的 `来源性质` 字段写明「非本工具抓取、不构成联网复核证据」），并在 diff 记录第一节以警示块标出 |

## 五、脱敏门禁：两类命中及处理（**未改门禁，改的是输出**）

新增 34 份全文后，`tools/check-desensitize.mjs` 报出 1 处硬命中与 2 处需语境档。两类都核查过，**硬命中是我自己的输出格式问题，不是内容问题**：

| 命中 | 位置 | 性质 | 处理 |
| --- | --- | --- | --- |
| 「手机号」硬命中（号码形态：三位数字＋掩码＋四位数字） | `sources/全文/L06.md` 元数据行 | **误报**。该处是主源 SHA256，哈希里的连续数字被当成被掩码手机号；已回查原页面缓存确认该页**不含任何手机号** | **不改脱敏规则**（它是硬门禁），改 `tools/提取全文.mjs` 的输出：SHA256 只显示前 16 位并与邻接文字隔开；完整值仍留在 `sources/.原文缓存/*.json` |
| 「公司全称（需人工判）」 | `sources/全文/L11.md` 第 324 行 | **误报**。原文是《民法典》第七十六条对法人类型的通用列举（营利法人包括有限责任公司、股份有限公司和其他企业法人等），**不是具体工作单位名称** | 已核官方页缓存原文确认；属「需人工判」档，不入硬命中。**不作改动**（改法条就是篡改原文） |
| 「公司全称（需人工判）」 | `sources/全文/L11.md` 第 1052 行 | 同上，《民法典》第二百六十八条 | 同上 |

处理后：**硬命中 0 处，需语境档 2 处**（即上表两处《民法典》原文），退出码 0。

> **本记录自己也踩过一次这个坑**：第一版把那个被误报的号码串**原样引用**在正文里，于是本文件自身又触发了一次硬命中（扫描器对 docs/ 一视同仁）。已改为只描述号码形态、不照抄字串。写留痕时照抄触发串，等于自己制造一次泄露告警——这一点值得记住。

> 这里能看出「机械扫描 + 人工核实」的分工：扫描器把两类情况都报了，人工核实后一类改了输出格式、一类确认为法条原文不动。**两头都不省**——只信扫描器会把法条当成泄露，只信自己会漏掉真泄露。

## 六、局限与未验证边界

1. **diff 与排版判据都不证明完整性**：只核对写进去的摘录行，不核对「该条该不该有」「有没有漏摘」。完整性靠人工与 `sources/法规清单.md` 的核验状态列。
2. **不证明版本现行性**：页面可能是已被取代的旧版。本仓库已命中四例「旧版页面不自我标注已被取代」（工伤保险条例、反不正当竞争法、住房公积金管理条例、N01），版本判断见 `docs/核实记录/源-版本复审-2026-10-03.md`。
3. **不证明条号归属**：只认字符连续出现，不判断条文是否属于该章该节。
4. **单时点快照**：全部原文为 2026-10-03 抓取；政务站改版后需 `node tools/抽原文.mjs --all --force` 重抓复核。
5. **S02 为本地人工核对件**，不构成联网复核证据（见第四节）。
6. **全文提取的「条数」是页面里「第N条」标记的计数**，不等于法定条文总数；页面若为分片页（如最高检《民法典》合同编页只有 526 条），提取结果就是那一编——本工具**不跨页合并**（合并即拼接，会被守恒校验拦下）。
7. **未与 HTML 版互校的页面**：N01 的规定全文取自官方 docx 附件（该规定在中国政府网没有 HTML 全文页）；docx 段落顺序与正式排版一致，但未与其它版本逐字互校。
8. **未改动 `sources/条文摘录.md` 本身**。它是全书「依据」栏的底本，工具只读它；排版件写在 `sources/条文/`，全文写在 `sources/全文/`，都是**新增**，不替换既有底本。

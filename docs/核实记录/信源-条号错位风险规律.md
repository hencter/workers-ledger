# 信源核验记录：条号错位风险规律

记录人：信源核验员
记录日期：2026-10-03（东八区）
适用范围：本仓库全部条目的「依据」栏引用核对

---

## 一、这份文件回答什么问题

**「条号存在、内容却对不上」这类错误，什么时候会发生？**

工具校验脚本（`tools/check-sources.mjs`）只比对页面的「修正／施行」关键词与链接可达性。它能发现「链接失效」和「页面出现了比注册表更新的版本日期」，但**发现不了「同一个条号在两个版本里指向完全不同的规则」**——因为两个版本的页面都能访问、都写着「现行有效」、都不报错。

这类错误只有逐条打开原文比对才能发现。本文件把它的成因、形态和判定方法固定下来。

## 二、规律：条号错位有两类成因

### 类型① 整部法规整体重编号

修订时对条文做**大规模挪位**，导致**大部分条号发生位移**。旧版条号会指向完全不同的规则。

**典型案例：《工伤保险条例》2010 年修订**

| 内容 | 2003 年原文（旧版） | 2010 年修订后（现行） |
| --- | --- | --- |
| 停工留薪期 | 第三十一条 | **第三十三条** |
| 一级至四级伤残待遇 | 第三十三条 | **第三十五条** |
| 五级至六级伤残待遇 | 第三十四条 | **第三十六条** |
| 七级至十级伤残待遇 | 第三十五条 | **第三十七条** |
| 工亡待遇 | 第三十七条 | **第三十九条** |
| 行政复议与诉讼 | 第五十三条 | **第五十五条** |

另有两处**实质内容修改**（不只是挪位）：
- 第十四条第六项：旧版「在上下班途中，受到**机动车事故伤害**的」→ 现行「在上下班途中，受到**非本人主要责任**的**交通事故或者城市轨道交通、客运轮渡、火车**事故伤害的」。
- 第三十九条第三项：一次性工亡补助金标准由「**48 个月至 60 个月**统筹地区上年度职工月平均工资」→「**上一年度全国城镇居民人均可支配收入的 20 倍**」。两者金额相差可达一倍以上。

**识别信号**：条例类文件的一次修订若涉及「增加一条」「删去一条」「第 X 条改为第 Y 条」这类表述，基本就是整体重编号。

### 类型② 单条或局部条文位移

修订**不改变总的条数**，只把个别条文挪到别的位置，或新增条文插在中间导致其后条文依次后移。

**典型案例：《反不正当竞争法》2025 年第二次修订**

| 内容 | 2019 年修正本 | 2025 年第二次修订本（现行） |
| --- | --- | --- |
| 商业宣传 | 第八条 | 第九条 |
| **商业秘密** | **第九条**（第四款为定义） | **第十条**（第四款为定义） |
| 有奖销售 | 第十条 | 第十一条 |

**识别信号**：条文总数没变，但个别条号的内容换了主题；或者新增条文插在前部，导致后续所有条号 +1、+2。

## 三、可操作的判定方法：拿到一部法规，怎么判断它属于哪一类

按以下顺序做，每一步都有明确的判定产物：

### 第 1 步：读页内「版本说明」，数事件次数

官方全文页通常在标题下有一行带全角括号的版本说明，形如：

> （1994年7月5日……通过　根据2009年8月27日……第一次修正　根据2018年12月29日……第二次修正）

- **只有一次「通过」，没有「修正/修订」** → 该法无重编号风险，直接用。
- **有「修正/修订」记录** → 进入第 2 步。

### 第 2 步：取修正/修订决定原文，看它怎么改

到中国人大网、中国政府网或国家行政法规库找那份《关于修改〈X〉的决定》。**重点看它用的是哪种表述**：

| 决定里的表述 | 含义 | 风险类型 |
| --- | --- | --- |
| 「将第 X 条修改为……」 | 原位改内容，条号不变 | 低风险（内容可能变，条号不动） |
| 「增加一条，作为第 X 条」 | 插入新条，其后条号后移 | **类型②** |
| 「第 X 条改为第 Y 条」 | 整体挪位 | **类型①** |
| 「删去第 X 条」 | 其后条号前移 | **类型②** |
| 「对条文顺序作相应调整」 | 明确重编号 | **类型①** |

### 第 3 步：核对该法当前条号总数与结构

用「条号出现在行首」的方式提取官方页的条文，数总数。若与记忆中或旧资料里的总数不一致，就是重编号了。

### 第 4 步：对同一部法至少取两个来源交叉比对

本次实践中，正是靠「中国政府网的修改决定原文」发现了《工伤保险条例》取数用错版本。**单一来源无法自证版本正确。**

### 第 5 步：引用时**在依据栏写清版本与施行日期**

这是最省事的防线。核验员自己最近的一次误报，根因就是**没有先看引用自带的版本标注，而是直奔自己手头已有的版本**。详见第五节。

## 五、核验员自己踩过的坑：版本拿错会制造**假阳性**

> [!danger] 这一节比前面所有内容都重要
> 上面两条规律讲的是「正文可能引错」。但本次实践中还出现了反向风险：**核验员因为拿错版本，误判正文引错了。**

**事情经过**：

1. 全仓审计时，核验员读到 `book/06-在职与离职后的红线.md` 6.12 引用「《反不正当竞争法》（2025-06-27 第二次修订，2025-10-15 施行）第十条第四款」。
2. 但核验员手头有的是该法 **2019 年修正本**（此前为核对另一条而下载的）。
3. 用 2019 版比对，发现「第十条 = 有奖销售，只有三项，没有第四款」，于是判定**条号不存在**，并作为「全仓唯一一处硬错」上报，措辞是「该条号在现行法中不存在」，非常肯定。
4. **这个判定是错的。** 2025 年第二次修订把商业秘密从第九条移到第十条。正文引用在其标注的版本下完全正确。
5. 核验员在后续补登阶段，改用最高人民法院公报公布的 2025 年第二次修订本复核，自行发现并更正了误报。

**根因（一句话）**：**看到引用就去自己手头的文本上查，没有先读引用自己标注的版本。**

**由此得到的强制动作**（已作为本仓库的核对纪律）：

1. **先读版本标注，再取文本。** 引用里若写了版本日期，取数前先确认自己手上的文本就是那个版本。
2. **手头文本与引用标注不一致时，默认是文本错了，不是引用错了。** 除非能证明引用标注有误。
3. **任何「某条号不存在」的结论，在发布前必须用引用所标注版本复核一次。** 否定性结论的杀伤力最大，因为它是「证明不存在」，而拿错版本最容易得出「不存在」。
4. **同一部法有两个以上有效版本并存时，结论里必须写明引用的是哪一版。**

**为什么这条规律值得单独成文**：它解释了本仓库为什么坚持要 `核对日期` 字段——**核对者自己也会用过期的版本**。一次核对不够，需要定期复核；复核时不仅要看链接是否可达，还要看**版本是否还是当初那个**。

# 侧栏展开、HTML 语义化与 SEO：把「看着没问题」变成可断言

**日期**：2026-10-03
**起因**：两个要求——① 侧栏数字要能点开就地跳转阅读；② 按 W3C 语义化改模板，保证 SEO 与爬虫可读。

## 一、侧栏：链接与按钮分开，状态只有一个来源

改前只有「当前节」展开，其他节必须点进去才能看条目。

采用 **W3C ARIA 的无障碍展开（disclosure）模式**，每个节一行放**两个元素**：

- `<a class=nav-sec__link>`：节名，负责**跳转**（主路径，保持不变）；
- `<button class=nav-sec__toggle aria-expanded aria-controls>`：负责**就地展开/收起**。

**为什么不是一个可点的标题**：`<a>` 没有「展开」语义，读屏不会播报成可展开控件，空格键也触发不了；按钮没有「跳转」语义。把两件事塞进一个元素必然牺牲一件。也**没有用 `<details>/<summary>`**：那会让详情折叠组只认一个 summary 作为交互入口，从而失去「点节名直接进该节」。

**无脚本可用的做法**：收起不用 CSS 类，而用 **`hidden` 属性**（语义：读屏与爬虫认定内容不存在）。服务端渲染时**不加** `hidden`，所以脚本未启用时全部条目平铺可见；脚本跑起来后才收起非当前节。`--check-archetype home` 之外的入口同样如此。

键盘：焦点在节控件上时，`↑/↓` 在节之间移动焦点、`←/→` 收起或展开当前节。只接管焦点落在节控件上时的方向键，其余一律不拦截。

## 二、抽屉：`hidden` + `inert`，不再两个状态来源

移动端抽屉原来用 `body.nav-open` 类切 CSS 显隐，按钮上另写 `aria-expanded`——**两个状态来源**，一旦不一致，读屏播报的会是「已收起」而内容其实在大纲里。

改为：

- 面板显隐由 `hidden` 决定，`aria-expanded` 与它同处同步；
- 关闭时面板 `inert`；**主区只在抽屉打开时** `inert`（否则等于把正文从无障碍树里摘掉）；
- 桌面端把 `hidden`/`inert`/`aria-expanded` **全部清掉**——桌面根本没有抽屉这回事，留着只会误导读屏；
- `body.nav-open` 保留但只管滚动锁定（`overflow: hidden` 是视觉行为，不是语义状态）。

## 三、新增 `site/checks/semantic-check.mjs`：把语义变成断言

语义化不是「看着顺眼」，它决定爬虫能否正确解析结构、读屏能否按地标跳转。CSS 里看不出来，也没有编译错误，只能靠断言。共 **23308 项断言**，覆盖：

| 类别 | 断言 |
| --- | --- |
| 文档基础 | `<!DOCTYPE html>`、`<html lang>`、`<title>` 非空、meta description、canonical |
| 结构 | `id` 全文档唯一、恰一个 `<main>`、skip-link 目标存在、恰一个 `<h1>`、**标题不跳级** |
| 元素语义 | `<time>` 带 `datetime`、`<img>` 带 `alt`、`<a>` 不嵌套、列表直接子元素只能是 `li` |
| 无障碍 | 地标齐全、多个 `<nav>` 都有可区分名字、`aria-labelledby/describedby` 目标存在、**展开控件的 `aria-expanded` 与面板 `hidden` 一致** |
| 机器可读 | 明文示例：`<script type="application/ld+json">` 存在、可 `JSON.parse`、是对象、有 `@context`/`@type`；`og:title/description/url` 齐备 |

### 由此抓出的真问题（都已修）

1. **15 个节页标题从 `h1` 直接跳到 `h3`**（缺 `h2`）：条目卡片用 `<h3>`（为首页设计，那里上面有 `<h2>`），但节页里 `<h1>` 之后直接就是卡片。`entry-card.html` 改为 `<h2>`——该模板**只被 `section.html` 使用**（首页检索结果另有自己的模板，那里的 `<h3>` 位于 `<h2>`「检索与筛选」之下，是对的）。
2. **抽屉的 `aria-expanded=false` 与面板可见不一致**（见第二节）。

## 四、`keepEndTags = true`：Hugo 删掉 `</li>` 会让结构不可机械验证

调试中发现 `hugo --minify` 默认**删掉可选闭合标签 `</li>`**（HTML 规范允许省略）。删掉之后，`<ul><li>…<div>…</div><ul>…</ul></ul>` 里就找不到「哪个 `ul` 是哪个 `ul` 的子元素」了——任何按嵌套解析页面的工具（我们的语义断言、第三方爬虫、无障碍检测）都会把内层 `<ul>` 误判成外层 `<ul>` 的直接子元素。

**规范允许省略 ≠ 无害**：省略之后结构信息只剩浏览器的自动补全，机器读不出来。已在 `site/hugo.toml` 设 `minify.tdewolff.html.keepEndTags = true`，代价是每页几个字节。

## 五、这道断言我连踩五个坑，全部留在这里

写校验器比写模板更难，因为这五个坑**都表现为「产物有问题」**，而实际上产物是对的：

| # | 坑 | 症状 | 教训 |
| --- | --- | --- | --- |
| 1 | 深度只数同名标签 | 第一个 `<li>` 里的 `div/a/button` 全落在 depth=1，被当成 `<ul>` 直接子元素 | 嵌套要按**所有**元素算 |
| 2 | 标签正则 `[^>]*?(\/?)>` 对未加引号的属性贪婪不足 | `<a href=/x/y>` 里 URL 的 `/` 被当成自闭合斜杠，`<a>` 被判为 void，深度一路漂到负数 | minify 会去掉属性引号；属性值必须显式识别三种形态 |
| 3 | 先自增深度、再判断 `depth===1` | 目标元素自己被记成自己的直接子元素 | off-by-one：**先判断、后自增** |
| 4 | `<!DOCTYPE html>` 与注释被当成普通标签压栈 | 名为 `!doctype`、`!--` 的元素进栈，栈整体错位一位，`</a>` 配到 `<header>` | 扫描时必须先丢弃注释与 DOCTYPE |
| 5 | 用「全文档祖先栈」做判据 | 任何一个漏掉的开标签都让栈错位，凭空产生 **330 项假阳性** | **判据越窄越可信**：最终只依赖它真正要验证的 `ul/ol/li` 三种标签 |

第 5 条的结论写进了代码注释：**最终判据收窄为「列表的直接子元素里有没有列表」，只扫描 `ul/ol/li`**。用同一份产物复核：最小状态机报 **0 处**，而全文档栈报 330 处——**产物是对的，判据是错的**。

> 一条通用教训：当校验器报出大量同类失败时，先怀疑判据，再怀疑产物。本项目这次五个坑全部属于前者，若直接按报错去改模板，会把正确的结构改坏。

## 七、局限与未验证边界

1. **断言跑在服务端产物上，不执行 JavaScript。** 因此对「由脚本代管 `aria-expanded`」的控件（移动端抽屉按钮）只校验其**前提**——SSR 时面板必须可见，否则脚本未跑时读者会看到空白；不校验脚本运行后的最终状态。要覆盖那一段需引入真实浏览器，本项目暂不引入依赖。
2. **不替代专门的 HTML 校验器。** 这里只覆盖影响爬虫解析、无障碍导航与结构化数据的那些规则，不做完整 HTML5 合规检查（例如元素内容模型的全量约束）。
3. **`keepEndTags` 只影响 HTML 压缩，不改变渲染结果**；已实测 `</li>` 与 `<li>` 数量各 350、配平。
4. **`inert` 的浏览器支持**：现代浏览器均支持；不支持时最坏情况是关闭状态下的抽屉内容仍可被焦点访问，不影响无脚本可用性。
5. **未做真机/读屏实测**：以上都是机械断言与人工审读，没有用屏幕阅读器实际走一遍。这是本项目的一个已知空白。

{{- /* 发布配置读取器 —— 从 Hugo data 里取 site.config.json 的内容。 数据由 tools/build-site.mjs 在生成阶段写入 site/data/site.json， 来源是仓库根唯一的 site.config.json（改域名、改仓库只改那一个文件）。 ## 为什么绕这一道 - 不写进 hugo.toml：那会出现**第二个真相源**，改一个忘一个的那天， 页脚链接会指向已废弃的仓库，而页面看起来完全正常； - 不用 resources.Get "site.config.json"：Hugo 在 site/ 下**读不到**仓库根的文件 （实测该方式取不到值，链接不渲染）。 由生成脚本转成 data 最稳，且来源仍只有一份。 取不到时返回空串，调用方用 {{ with }} 决定是否渲染—— **不要在这里退回硬编码地址**：硬编码正是要避免的东西。 issueURL 是「新建 issue」的基地址（不含预填参数）。预填参数由 partials/纠错链接.html 用 querify 拼——**不要手拼查询串**：中文、井号、换行都必须正确百分号编码， 手拼容易漏（把 `#` 原样写进 URL，浏览器会当成锚点，后面的正文全丢）。 */ -}} {{- $cfg := hugo.Data.site | default dict -}} {{- $repo := $cfg.repo | default "" -}} {{- return (dict "repo" $repo "repoURL" ($cfg.repoURL | default (cond (ne $repo "") (printf "https://github.com/%s" $repo) "")) "issueURL" (cond (ne $repo "") (printf "https://github.com/%s/issues/new" $repo) "") "publishUrl" ($cfg.publishUrl | default "") "domain" ($cfg.domain | default "") "hosting" ($cfg.hosting | default "") ) -}}
